For heavy Claude Code workflows

Remember the work, not where you started it.

Reup brings your local Claude Code CLI work into one persistent view across projects and ordinary terminal sessions. Find the task you remember, see what needs you, and resume with the latest recorded request, response, path, and branch in view.

One continuity loop

Find → know what needs you → resume in context

Reup is useful when your session history has outgrown your memory of directories and terminal tabs.

01

Find the work

Search projects and sessions together. Use titles, aliases, paths, branches, and structured filters first; search transcripts or paths targeted by write/edit tool calls when the clue is buried deeper.

reup search --deep "oauth callback"
02

Know what needs you

See live processes and locally anchored background tasks without opening every terminal. Fresh, non-superseded Claude-reported state takes precedence; only a reported PID or verified lock establishes a live process.

reup
03

Resume in context

Check the latest recorded request and response, plan, TODOs, write/edit targets, path, branch drift, and health signals before starting another Claude Code process.

reup resume 8f3a2c10

Local by design. Transcript analysis stays on this machine; Reup does not rewrite Claude-owned transcripts, sends no telemetry, requires no Reup account, and binds the web dashboard to 127.0.0.1. The TUI, web, and configuration flows automatically register or repair reversible Claude Code attention hooks and print reup attention remove as the undo command. Account-usage requests to Anthropic remain off until reup usage setup; remove that opt-in integration with reup usage remove.

Use the right view

Reup complements Claude Code's built-in tools

Claude Code already has strong session features. Reup is for the continuity gap between saved history, ordinary interactive terminals, and the next safe resume.

Workflow comparison between Claude Code resume, Agent View, and Reup
Question Claude /resume Claude Agent View Reup
Primary job Switch to a saved conversation Dispatch and operate background sessions Find, triage, and resume local work
Local scope Current worktree by default; Ctrl+A widens to all projects Background sessions across projects Discovered CLI history plus matched live processes and managed tasks
Ordinary terminals Saved conversations are available in the picker Interactive sessions elsewhere appear only after they are backgrounded Includes live interactive sessions when Claude reports or local evidence matches them
Before continuing Preview, name, branch, age, and message count Current activity, state, peek, reply, and attach Latest request and answer, tool targets, branch/path checks, health, and usage context
Important boundary An unrelated project produces a copied cd … && claude --resume … command Designed around the background-session workflow Local CLI data only; no Claude desktop, web, or remote-history aggregation

Native behavior summarized from Claude Code's official session documentation and Agent View documentation. Agent View is a research preview, so details may change. Its JSON inventory can retain background tasks reported as working or blocked after their process exits. Reup keeps those rows for safety, but presents one without a PID only when it maps to a resume-visible discovered session or a verified live lock; age and orphanable markers do not make that decision.

Choose the local interface

Fast in the terminal. Glanceable in a tab. Native in VS Code.

The interfaces serve different moments of the same local workflow; none is a cloud sync surface.

Terminal UI

Keyboard-first scanning, filtering, preview, and resume with reup.

Web dashboard

Live local updates and a persistent overview with reup web.

VS Code

Workspace-first discovery and a focused resume card inside the editor.

CLI

Human-readable commands and machine-readable output where supported.

Depth when you need it

More than a list of titles

Search by the clue you remember

Metadata, qualifiers, aliases, deep transcript search, adaptive ID prefixes, and reverse lookup for paths targeted by write/edit tool calls.

Evidence, not decorative badges

Reported state is applied per valid field. Locks and hooks remain useful local evidence; transcript activity can supply an inferred hint. Source detail is not yet equally visible in every interface, so labels remain guidance rather than proof.

Warnings with an action

Missing paths, branch drift, interrupted turns, expiry, compaction, and index findings include an explanation rather than a bare risk color.

Archive and delete are different

Archive is reversible Reup metadata. Permanent deletion is separate, explicit, confirmed, unavailable for active sessions, and cannot be undone.

Current access

Build the source beta

Reup currently requires Node.js 20 or newer, the Claude Code CLI, and local Claude Code session history. It is not published to npm yet and there is no tagged public release. The source path below installs the CLI and local web dashboard.

Release-candidate assets will be listed on GitHub Releases once published. Until stated otherwise there, treat Windows and macOS binaries as unsigned and macOS builds as not notarized. 

git clone https://github.com/patriziofilloramo/claude-code-reup.git reup
cd reup
npm ci
npm run build
npm link
reup

Optional VS Code extension

The CLI install does not add the extension. Build and install its local VSIX separately; the script installs extension build dependencies when needed. 

npm run install:extension

Remove a source install

Remove integrations before unlinking so Claude Code settings do not retain them. 

reup attention remove
reup usage remove  # only if enabled
npm unlink --global @patriziofilloramo/reup
